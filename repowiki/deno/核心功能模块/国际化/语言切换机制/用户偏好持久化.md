## 简介
本文档详细说明了用户语言偏好持久化的实现机制。系统通过前端状态管理、GraphQL通信、后端数据访问层与数据库协同工作，确保用户语言设置在跨设备、跨会话中保持一致。文档涵盖从前端store变更到后端同步、数据一致性保障、跨设备同步及数据迁移的完整流程。

## 项目结构
项目采用分层架构，主要分为前端（pc、uni）、后端（deno）和代码生成（codegen）三大模块。前端负责用户交互与状态管理，后端提供GraphQL API与数据持久化服务，codegen模块自动生成数据访问对象（DAO）与模型代码。

## 架构概览
系统采用前后端分离架构，前端通过Vuex管理用户状态，利用GraphQL mutation将语言偏好同步至后端。后端通过DAO层操作数据库，确保数据一致性，并通过缓存机制提升性能。

```mermaid
sequenceDiagram
participant 前端 as 前端 (pc/uni)
participant Store as 用户状态 (usr store)
participant GraphQL as GraphQL API
participant 后端 as 后端服务 (deno)
participant DAO as 数据访问层 (lang.dao)
participant DB as 数据库 (base_lang)
前端->>Store : 用户更改语言设置
Store->>GraphQL : 调用 setLang mutation
GraphQL->>后端 : 接收请求并验证
后端->>DAO : 调用 updateLang 方法
DAO->>DB : 执行 UPDATE SQL
DB-->>DAO : 返回结果
DAO-->>后端 : 返回操作结果
后端-->>GraphQL : 返回响应
GraphQL-->>Store : 更新成功
Store->>前端 : 触发界面刷新
```

### 国际化管理分析
系统通过本地缓存与服务器协同管理国际化资源，优先使用本地缓存，缺失时从服务器获取并缓存。

```mermaid
flowchart TD
Start([初始化国际化]) --> CheckEnable["检查 VITE_SERVER_I18N_ENABLE"]
CheckEnable --> |禁用| UseCode["直接返回代码"]
CheckEnable --> |启用| GetLang["获取用户语言设置"]
GetLang --> CheckCache["检查 i18nLblsLang 缓存"]
CheckCache --> |无缓存| InitCache["初始化缓存对象"]
CheckCache --> |有缓存| CheckVersion["检查版本一致性"]
CheckVersion --> |版本不一致| ClearCache["清空缓存"]
CheckVersion --> |版本一致| UseCache["使用现有缓存"]
InitCache --> SaveCache["保存到 localStorage"]
ClearCache --> InitCache
UseCache --> CheckKey["检查键值是否存在"]
CheckKey --> |存在| ReturnCached["返回缓存值"]
CheckKey --> |不存在| FetchServer["从服务器获取"]
FetchServer --> UpdateCache["更新缓存"]
UpdateCache --> SaveCache
ReturnCached --> End([完成])
SaveCache --> End
```

## 性能考量
系统通过多级缓存机制优化性能：前端使用localStorage缓存语言资源，后端DAO层提供数据访问缓存，减少数据库查询次数。同时，GraphQL的精准查询避免了不必要的数据传输。

## 故障排除指南
常见问题包括语言设置不生效、国际化资源加载失败等。排查时应检查：1）localStorage中lang值是否正确；2）GraphQL mutation是否成功；3）后端日志是否有数据库错误；4）缓存版本是否一致。

本系统通过前后端协同实现了用户语言偏好的完整持久化方案。前端状态管理与后端数据访问层紧密结合，配合缓存机制，确保了用户体验的一致性与系统的高性能。未来可扩展支持更多语言动态加载与用户自定义翻译功能。
